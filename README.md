# Pixel Block Jam 网页复刻

目标是在网页端重建《Pixel Block Jam》的画面、交互、关卡逻辑、动画和声音；网页版本完成后再评估微信小游戏移植。

本仓库以用户提供的本机视频为主要参考，逐关建立网页版本。证据会区分直接观察、推断和暂定实现，原始视频与逐帧工作文件留在被忽略的 `.research/`，不进入代码仓库。

## 本地预览

```sh
npm install
npm run dev
```

打开 `http://127.0.0.1:4173/`。游戏运行本身无第三方依赖；安装开发依赖是为了运行下面的 Playwright 端到端测试。

## 当前实现

- Canvas 按源视频竖屏比例绘制，Level 1–13 都有独立棋盘数据。Level 1 开局使用 `00:02.3` 源帧中的 474×219 棋盘裁切；四个上排操作格分别复用 `00:02.0` 中未被教程手势遮挡的 121×121 源裁切。Level 2 开局使用 `00:09.5` 的 563×666 整面板裁切，包含 5×2 操作格，并在浏览器中整面板逐像素回归；首个有效红槽操作后按 60 fps 源片时间轴绘制连续游戏面板，并用真实鼠标 E2E 对齐三色交叠进度。偏离原片动作窗口或精确停靠点时，切换自由路线：槽沿实际拖动路径碰撞同色像素，松手后继续该颜色的收集进度；这条回退路线有真实鼠标 E2E 和录屏，但不声称是原片中未展示的玩法。8 个原作路线锁帧的原片、网页和像素差异图及接触表保存在 `.research/events/level2-real-input-frame-audit/`。Level 3 使用 `00:19.9` 中 478×276；Level 5 使用 `01:17.0` 中 492×198；Level 6 使用 `01:40.0` 中 435×334 的源帧裁切；这些关卡的静态棋盘都按同尺寸源帧裁切逐像素回归，格子清除或拆分时再按运行状态覆盖。Level 4 使用 `00:47.3` 的源帧格像素，只比较未被红槽及其阴影遮挡的区域；Level 7 使用 `02:14` 帧的 37×20 墙面，排除被顶部操作格及 8 px 阴影遮挡的位置；Level 9 使用 `03:33` 帧的 487×353 棋盘裁切，排除顶部操作格及阴影遮挡区；Level 12 使用 `06:09` 帧的 482×312 棋盘裁切，排除操作格和双层槽遮挡区；Level 13 使用 `06:26` 的 474×373 糖果墙裁切，开局全区逐像素回归，并确保飞碟清除后切回状态绘制。Level 1 未被手势遮挡的操作格区域也逐像素比较；黄色槽满格复用 `00:04.3` 源帧的槽内纹理，中心 173×170 区域差异率约 0.19%。Level 8、10、11 的像素墙已从录屏关键帧按网格采样；Level 8 使用约 8 px 源格距的 60×39 开局墙，底图取自无触控圆环的第 51 帧（约 `02:54.83`）485×312 源裁切；源图对比和浏览器 Canvas 回归均为 0 差异。第 31 帧可见的黄色圆环仍作为短暂交互反馈证据，触发条件待验证；收集掉落或拆分的格子再按运行状态覆盖绘制。Level 8 还使用三色 8×8 体素贴图绘制槽内碎块，并核对 44%→100% 的连续关键状态。Level 10 从 `04:23` 未操作帧重采为 37×14、518 格；实际为 20 个收集槽、3 条管道，网页开局棋盘/操作格/管道无遮挡段/前四行槽位均有逐像素回归，底部槽行被视频号控件遮挡后采用 Canvas 绘制。Level 11 上下盘各按 `05:23` 开局帧采样为 56×17 格；两块棋盘底图裁切与网页 Canvas 均逐像素一致，槽位和框体继续由 Canvas 重建，下盘槽位区被视频号控件遮挡。Level 12 的 37×24 黄 T 形内层、紫色侧区和蓝色空区按开局帧还原，受槽体遮挡的底部中央格为版式推断；先填黄色内层再解锁紫色外层。Level 13 的飞碟填槽动画按录屏过程校准。关键帧重建不等于完整动作逐帧验证。
- Level 3 的动态源片覆盖 S5 `00:19.9–00:42.9`，共 1,380 帧、23 秒；默认首拖紫槽按媒体时钟回放，真实浏览器呈现 1,375 帧，91 个对齐画面样本的无遮挡主面板均为零像素差，并在 23.00 秒才收集最后一格进入 Level 4。回放中可从画面上的蓝槽真实接管：3.25 秒时从 `x=51..351,y=480..672` 拖动后，蓝色进度由 18% 到 83%，源片暂停并继续自由操作。录屏和报告在 `.research/recordings/level3-visible-drag/`。
- Level 11 的部分清除现在继续使用源棋盘底图，只覆盖已清空格，避免拖动后逐帧重绘约 1,900 个未变化像素。Headless Chrome、DPR 1 的真实紫槽拖动中，Canvas 帧回调内线性渐变数 P95 从修改前 978 降到 94；回调耗时 P95 从 1.6 ms 降到 0.8 ms，帧间隔 P95 为 16.7 ms。清空底色取自 `05:24.0` 源帧，网页真实拖动 E2E 确认下盘不变。
- Level 1 开局面板和黄色扫墙均从源裁切保留 744 px，最后 12 px 淡入重绘外框；E2E 逐行检查边缘连续性。运行 `npm run audit:level1-tutorial -- <原录屏路径>` 可将原录屏 `00:02.300–00:02.717` 的 26 个真实解码帧与浏览器画布同时间帧并排输出。教程手势只播放一次并停在末帧；冷启动 E2E 确认只播放一次、没有回跳，57 帧逐帧比较中手势和黄色槽的可见差异均为 0。黄色扫墙只播放 `00:02.8–00:04.3` 面板片段；三轮重复 E2E 每轮采到 60–64 个视频帧回调和 64–66 个画布样本，棋盘及活动黄槽逐像素一致，整面板差异 0.37%。绿段每轮比较 49–57 帧、红段 79–87 帧，采到的每帧棋盘差异均为 0。绿色和红色复用对应源帧的棋盘裁切，槽位仍由网页状态驱动；触屏 E2E 检查绿色移动连续、黄色稳定、红色不误移且仍可继续拖动。
- 拖动收集按颜色、独立槽位和复合槽形逐格碰撞；完成度实时更新并播放像素碎块动画。Level 1 教程期间隐藏道具栏，Level 2 起显示四格；源视频 Level 2 可见四个锁定格，Level 13 时前三项各有 2 次。时间冻结、拆分锤和飞碟可点击，下一项显示第 16 关解锁。Chromium 实际画布指针路线已覆盖 Level 1–13，清空 Level 13 糖果墙并进入第 14 关通关转场；这验证当前矩阵和交互路线可通关，不证明未出现在源视频中的第 14 关内容。
- 无关卡预览参数时，页面先显示约 1.8 秒中文启动画面，再进入 Level 1；启动画面的立体中文标志、彩色方块盒和加载条由 Canvas 绘制近似。`?previewLevel=1` 至 `?previewLevel=13` 保留即时校准入口。
- 设置、胜负和道具解锁均有中文网页交互。Level 9 奖励页按录屏呈现 78% 到 83% 的进度递增，并提供领取续关流程；Level 1 转场已按 102 张连续 60 fps 源帧校准：徽标从约 7.8 秒开始放大，8.0 秒到位并保持至约 8.52 秒，随后收缩，8.67 秒开始圆形揭示，8.8 秒左右第 2 关面板铺满；网页在 8.9 秒左右接入第 2 关。英文品牌文字替换为中文“像素方块大闯关”；徽标材质仍为 Canvas/CSS 仿制，不能视为原始 3D 素材。Level 1 品牌前奏会整屏绘制，E2E 检查未留下原先面板视频裁切的矩形接缝。Level 11 离散源帧显示紫色槽填充时主要清空黄色格，与网页当前按颜色绑定槽位的模型不一致；两盘后续清空顺序和联动还未核验。Level 12 双层槽的真实完成过程、启动画面的原始 3D 素材以及各道具动画仍需更多连续源帧。录屏未展示启动后的可操作主菜单。
- 用户确认录屏 AAC 双声道是原作游戏声音。Level 1 已从源视频 `00:02.3–00:08.85` 提取混合音轨：黄、绿、红扫墙分别跟随原画片段播放，并在末槽完成后继续覆盖约 0.6 秒原作过关音频；鼠标 E2E 已确认转场期间音轨仍在播放，黄色扫墙阶段还逐帧记录原声与原画的媒体时间，超过 45 组采样的最大偏差小于 60 ms。背景音乐和音效都开启时使用原声，单独关闭其中一项时切回合成音频以保持独立静音开关。原音轨没有拆分成独立音乐和事件音效。Level 2 从 S5 `00:09.5–00:19.3` 提取 9.8 秒 AAC 双声道混合音轨，在第一只红槽有效停靠后按源时间播放；459 组音画媒体时钟样本的 P95 偏差 37.2 ms、最大偏差 39.1 ms，转场中继续播放至 9.64 秒。设置页 E2E 验证音轨、视频与进度暂停，并从原位置续播。音乐和音效都开启时使用原声，任一项关闭时静音原声、回退到合成通道。

## 网页端端到端测试

```sh
npm run test:e2e
```

Playwright 使用本机已安装的 Google Chrome，固定单 worker 运行 Canvas 长拖动路线，并自动启动或复用 `127.0.0.1:4173`。覆盖启动画面自动进入 Level 1、Level 1 教程手势源片段播放、开局主面板与棋盘像素回归、操作格和满格黄色槽纹理像素回归、黄/绿/红真实拖动进度、中文全屏徽标转场无裁切接缝、Level 1–13 棋盘像素回归（Level 8、10、11 对照无遮挡源帧区域要求 0 差异）、Level 11 紫槽真实拖动、Canvas 帧预算和下盘不变、Level 10 的 518 格/20 槽状态和三条管道真实拖动、鼠标和 Chromium CDP 触屏的设置点击/继续与收集槽拖动、延迟音频解锁、Level 1–13 连续清关转场、道具栏锁定/解锁及 Level 9 奖励领取。

Level 1 E2E 覆盖开局图像、倒计时居中、底框裁切连续性、黄色槽满格纹理、鼠标与 CDP 触屏拖动。教程手势的 26 帧各自与源视频同帧比较；完整黄色槽在手指遮挡 `0%` 标记的范围之外保持稳定。网页只播放一次 0.433 秒手势并停在末帧，测试验证结束后槽体连续采样不变。触屏测试逐帧采样未操作的黄色槽，确认它在绿色扫墙期间保持稳定；也检查绿色连续上移、红槽仍在原位、托盘下排完整，随后真实拖动红槽验证游戏未卡住。另覆盖 Level 1/2 原声音轨播放、设置页暂停/续播、原声音画同步和三槽清空后的自动转场。历史进度关键帧图不再作为交互截图的验收依据。

`e2e/full-progression.spec.js` 根据当前关卡矩阵生成逐槽拖动路线，并通过 Chromium 真实 Canvas 指针事件执行；它验证格子映射、碰撞和整局进度的可达性，不证明玩家在源视频里的具体拖动路径。

本地调试可通过 `/?previewLevel=1` 至 `/?previewLevel=13` 直接检查关卡画面；`/?previewLevel=9&previewReward=1` 可查看 Level 9 奖励页。它们是校准入口，不代表关卡已完成复刻。

## 视觉对照

仓库内的 `scripts/compare-reference.mjs` 来自 Block Crush 的截图对比流程，可对齐源帧与网页截图的同尺寸裁切，并生成叠图、差异图和 JSON 报告：

```sh
npm run compare:reference -- \
  --actual .research/source-frames/replica-level3-opening-oct23.png \
  --reference .research/source-frames/video-level3-19_9-normalized.png \
  --reference-crop 59,197,478,276 \
  --actual-crop 59,197,478,276 \
  --out .research/source-frames/level3-comparison-opening
```
